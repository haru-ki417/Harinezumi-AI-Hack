# 企業向け面接

トップ画面で「面接官」を選び、「対人面接」または「AI面接」を選択して「この方式で面接を設定」へ進みます。
選択した方式は企業の設定画面（`/company`）に引き継がれます。企業アカウントを作成、またはログインしてください。
職種・対人/AI・所要時間・質問・確認項目を設定し、応募者ごとの招待を発行してください。
保存しても質問などの入力は消えず、同じタブでの画面移動・再読み込み後も企業ごとの下書きを復元します。
保存済みの面接設定を選ぶと、その内容を編集欄に読み込みます。変更した内容は保存してから招待を発行してください。
招待発行後は専用の確認画面（`/company/invitation?id=...`）へ進みます。
招待URLや参加コードをコピーして、普段使っているメール等で応募者に共有できます。
このアプリからメールを自動送信する機能はありません。

就活生はトップ画面の「就活生として面接に参加」を押し、次の画面（`/interviews/join`）で招待コードを入力します。招待URLから直接開くこともできます。
面接方式と記録内容への同意、機器の確認後、AI面接を開始するか、対人面接の入室許可を待ちます。
対人面接は企業の招待一覧から担当者が入り、入室を許可します。
対人面接ルームでは、以前と同じ心拍数・ストレスメーター・リアルタイムのストレス推移を確認できます。
各参加者が「心拍・ストレスの計測と相手への共有に同意する」をオンにすると、自分のカメラから計測を開始し、同じ面接の相手にも表示します。
未入室・共有オフ・カメラ停止・面接終了時は計測しません。画像は保存せず、同意した参加者の有効な数値だけを毎秒最大1件保存します。AIの面接集計には送りません。
面接終了画面と企業の集計画面に、心拍・ストレスの平均・最小・最大、有効データの秒数、30秒ごとの推移を表示します。応募者に見えるのは自分の計測値のみです。
「文字起こしを開始」で自分のマイクを認識し、確定した発言を自動保存します。各参加者が自分の端末で開始してください。停止・マイクオフで認識を止めます。接続が切れても未保存の発言を同じタブ内に保持し、接続復帰後に重複せず再送します。終了前に文字起こしを停止し、未保存の発言がないことを確認してください。
既存のバイタル共有ルームはトップ画面下部のリンク、または `/vital` から開けます。
同じブラウザーの再読み込み時は保存済みの参加認証で再開できます。
参加認証を失った場合や別の端末に移る場合は、企業が新しい招待を発行してください。

面接終了後は、就活生と企業の双方に「回答の振り返り」を表示します。発言を引用して、伝わった点・補足できる点・質問別の回答構成・次回の練習手順を確認できます。引用を押すと保存された会話へ移動します。深掘りで補った回答も同じ主質問にまとめます。回答構成は自分の経験を入れる記入式で、架空の実績や数字を作りません。
就活生は終了画面の「フィードバックを更新」、企業は集計画面の「集計を再作成」で作り直せます。以前の面接記録にも対応します。企業の確認項目・担当者メモ・選考判断・バイタルは、共有フィードバックの生成には使用しません。従来の企業専用集計・判断は引き続き企業だけが閲覧できます。

面接後、企業は招待一覧の「集計・判断を開く」から応募者ごとの専用画面（`/company/report?id=...`）へ進みます。
発言記録と根拠付きの集計を確認し、人間の判断・メモを保存できます。
AI集計には採用スコアや合否判定、心拍・ストレスによる適性判定を含めません。
引用から元の発言を確認できます。応募者には社内の集計・判断・メモを公開しません。

## 起動と設定

開発時は `backend` で `uvicorn app:app --port 8000`、`frontend` で `npm run dev` を実行し、`http://localhost:3001` を開きます。別端末への招待には下記の共有起動手順を使用してください。

| 環境変数 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | バックエンドのみ。設定するとAIの追加質問・集計・質問音声を使用 |
| `OPENAI_INTERVIEW_MODEL` | 面接用モデル。既定値 `gpt-4o-mini` |
| `OPENAI_INTERVIEW_TTS_MODEL` | 質問音声用モデル。既定値 `gpt-4o-mini-tts` |
| `OPENAI_INTERVIEW_TTS_VOICE` | 質問音声の声。既定値 `marin` |
| `HIRING_DB_PATH` | SQLiteファイル。既定値 `backend/records/hiring.sqlite3` |
| `HIRING_PUBLIC_URL` | バックエンドのみ。固定公開ドメインのHTTPSオリジン。設定するとローカル管理画面にもこのURLの招待リンクを表示 |
| `HIRING_SHARING_URL_FILE` | 公開URLを書いたローカルファイル。未設定時は `.sharing/url.txt` を自動検出。空文字で自動検出を無効化 |
| `NEXT_PUBLIC_API_URL` | 通常は未設定。同じHTTPSオリジンのAPIに接続。別APIを公開する場合のみ指定 |
| `BACKEND_INTERNAL_URL` | Next.jsが中継するAPI。既定 `http://127.0.0.1:8000`、Dockerは `http://backend:8000`。ビルド前に設定 |
| `HIRING_TURN_URLS` | バックエンドのみ。TURN/TURNS URLをカンマ区切りで設定 |
| `HIRING_TURN_SECRET` | バックエンドのみ。coturn等の共有秘密。認証済みの参加者に3時間有効の接続資格情報を発行 |
| `NEXT_PUBLIC_RTC_ICE_SERVERS` | 対人通話のICEサーバー配列（JSON）。未設定時はGoogleの公開STUNを使用 |
| `STEALTH_VITAL_CORS_ORIGIN` | 許可するフロントエンドのオリジン |

APIキー未設定時・AI通信失敗時は、定型質問と発言の抽出による集計で動作します。
画面には実際の処理方式が表示されます。AIへの送信内容は質問・確認項目・発言テキストです。
氏名やバイタルの専用フィールドは送信しませんが、発言本文に含めた個人情報は送信対象になります。
AI連携は[OpenAI Responses APIの構造化出力](https://developers.openai.com/api/docs/guides/structured-outputs)を使用します。

AI面接では「面接を開始」を押すと質問を読み上げ、読み上げが終わるとマイクによる回答の文字起こしを自動で開始します。
各主質問からの深掘りは最大3回です。直前の回答と同じ話題で既に確認した内容を見て、本人の行動・選んだ理由・結果の確認方法・学びの応用など、まだ説明されていない点へ質問を派生させます。十分に具体化した場合、回答を控える場合、残り時間が少ない場合は、次の主質問へ進みます。画面には主質問と深掘りの進み具合を表示します。
APIキー設定時はAIが会話に沿って質問を作成し、未設定・接続失敗時も回答内の表現から確認する観点を選んで進行します。フィードバックもAI生成とルールによる整理を画面上で区別します。[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)で形式を指定し、引用が実際の応募者の発言に存在するかサーバーで確認してから表示します。
話し終えたら「回答を完了」を押してください。最後の認識結果を受け取って回答を保存し、次の質問の読み上げと音声入力へ自動で進みます。
途中で音声認識が自然に止まった場合も、回答中は自動で再開します。無音だけでは回答を送信しません。
ブラウザーによって外部の音声認識サービスが使われる場合があります。認識非対応・権限拒否時は説明を表示し、テキストで回答できます。
APIキー設定時は[OpenAIの音声生成API](https://developers.openai.com/api/docs/guides/text-to-speech)で質問の音声を生成します。
未設定時・音声生成に接続できない場合は、ブラウザーの日本語音声を使用し、画面にも処理方式を表示します。
音声の実際の再生に合わせて面接官のアニメーションと「質問中」の表示が変わります。
読み上げ中は音声認識を停止し、質問が回答として入力されることを防ぎます。読み上げの停止・再生・音声オフも可能です。
音声が利用できない環境でも、質問文を読んでテキストで回答できます。
音声生成には認証済みの面接で現在提示中の質問だけを送り、音声は短時間のメモリーキャッシュにのみ保持します。
対人の映像・音声はWebRTCで相手に送信し、サーバーに録画・録音しません。
対人面接で保存した発言と、AI面接で「回答を完了」した回答テキストを面接記録として保存します。

企業認証・招待・発言・集計・判断はSQLiteに保存します。`records` はGitとDockerビルドから除外します。
Docker Composeでは名前付きボリュームに永続化します。サーバーの保存先をバックアップしてください。
本番のカメラ・マイク利用にはHTTPSを用意してください。標準構成は同一オリジンからAPI/WebSocketを中継するため、ブラウザー用API URLやCORSの変更は不要です。
`NEXT_PUBLIC_*` はフロントエンドの起動・ビルド前に設定します。
社外ネットワーク間の対人通話には、必要に応じてTURNサーバーを用意してICE設定に追加してください。
例：`[{"urls":"turn:turn.example.com:3478","username":"...","credential":"..."}]`。
現行の対人WebSocketは1ワーカーで動かします。複数台・複数ワーカーでの共有接続管理は未対応です。

## 別のPC・スマートフォンへ招待する

Windowsでは、依存関係のインストール後に次を実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Build-SharedInterview.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-SharedInterview.ps1
```

共有中の画面を更新する場合は、公開URLを維持したまま次を実行します。

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Update-SharedInterview.ps1
```

共有用は `frontend/.next-shared/<世代>` に毎回新しくビルドします。別ポートで参加画面・JavaScript・CSS・APIの読込を確認してから、フロントエンドだけを入れ替えます。ビルド失敗時は現在の画面を維持し、バックエンド・招待・面接記録・トンネルは更新しません。画面の入れ替えは面接中を避けて実行してください。

通常の開発は `frontend` で `npm.cmd run dev` を実行し、`http://localhost:3001` を開きます。開発用 `.next-dev`、通常ビルド `.next`、共有用の各世代は分離しているため、開発サーバーが公開用のJS/CSSを上書きしません。共有用の `3000` ポートで別の開発サーバーを起動しないでください。

スクリプトは公式のcloudflared 2026.9.3を取得し、公開されたSHA256を照合して起動します。バックエンド・本番フロントエンドは外から直接接続できないローカルアドレスに待ち受け、採用面接のAPIとWebSocketだけをNext.jsから中継します。URLとログはGit対象外の `.sharing` に保存します。

起動後は、普段の `http://localhost:3000/company` をそのまま使えます。招待確認画面が共有接続を自動で確認し、別端末で使える招待URLを表示します。「招待URLをコピー」で応募者へ送ってください。コードで案内する場合は、同じ画面の「コード入力用URL」も一緒に送ってください。公開URLの管理画面へ移動したり、再ログインしたりする必要はありません。

共有先が同じバックエンドにつながることを確認してからURLを表示します。接続停止時は古いURLや `localhost` のURLをコピーさせず、「接続を再確認」で再試行できます。共有先の変更は次回確認時に反映します。通常は15秒ごと・画面を再表示したときに確認します。応募者にインストールや企業アカウント作成は不要です。

これは試用向けの一時URLです。このPCと共有サービスを起動したままにしてください。共有を停止して開始し直すとURLが変わります。`Update-SharedInterview.ps1` による画面の更新ではURLを維持します。停止するには `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Stop-SharedInterview.ps1` を実行します。継続運用には固定のHTTPSドメインでフロントエンドを公開し、WebSocket Upgradeを転送してください。Quick Tunnelの制約は[Cloudflare公式資料](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)を参照してください。

TURNが未設定の場合、制限の強い企業Wi-Fiや一部の携帯回線間では、入室できても対人の映像・音声がつながらないことがあります。`HIRING_TURN_URLS` と `HIRING_TURN_SECRET` を実際の中継サーバーに合わせて設定すると対応できます。TURN自体の設置・通信確認は別途必要です。

## 計測の改善と確認範囲

顔未検出・露出不良・10fps未満・大きなフレーム欠損のデータからは心拍数を出しません。急なRGB変化や0.35秒を超える欠損で連続計測をやり直します。6秒以上の脈波を実際の時間間隔で解析します。HRVは15fps以上・12秒以上の信号を使い、ピークの時刻補間と不正な拍間隔の除外を行います。ストレスの基準値は少なくとも15秒にまたがる有効な推定値が必要です。

合成信号・低fps・欠損・顔未検出の回帰テストを行っていますが、実機の脈拍計との比較による精度検証は未実施です。数値は推定の参考値であり、医療診断・心理状態・採用適性の評価には使いません。照明・フレームレート・体動の影響については[計測条件を比較した研究](https://www.mdpi.com/1424-8220/21/24/8357)を参照してください。

```powershell
cd backend
.venv/Scripts/python.exe -m unittest test_hiring test_interview_ai test_interview_questions test_interview_feedback test_hiring_feedback test_hiring_edge_cases test_hiring_live test_hiring_vitals test_interview_speech test_interview_improvements test_measurement_validity

npm.cmd run typecheck
npm.cmd run test:hiring
npm.cmd run build
```

テストは一時データベースとAIの代替実装を使用し、実際のAI APIを呼び出しません。
